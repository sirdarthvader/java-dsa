# Interview Coaching Profile

## Ground truth

- Target: Senior software engineering roles; prepare for L5-level scope while
  allowing the hiring team to determine exact levelling.
- Background: 8+ years as a senior software engineer; framework, web platform,
  TypeScript, developer tooling, cloud, and frontend systems experience.
- Strength: practical, first-principles engineering. Gap: timed algorithmic
  interview fluency and consistent retrieval practice.
- Constraint: full-time work plus coursework and personal responsibilities.
- The user reports ADHD. This document treats that as an important planning
  constraint, not a clinical assessment. Professional care remains separate.

## Coaching contract

1. No shame-driven schedules and no all-or-nothing restarts.
2. We optimize return speed after a missed day, not an unbroken streak.
3. One completed, reviewed problem beats five half-started resources.
4. We will use evidence: timed mocks, error log, re-solves, and weekly review.
5. We will not use AI in a live interview.

## ADHD-aware operating protocol

### The daily floor

On a hard day, do the minimum viable session: 10 minutes to read a previously
solved problem, state its invariant aloud, and write one test case. The day is
not a failure; resume the planned session next time.

### The standard session

1. Write one micro-outcome: "solve and explain one sliding-window medium."
2. Put phone away, block YouTube/social feeds, open only editor + problem.
3. Do a 25-minute attempt timer. Stand/walk for five minutes.
4. Do one 25-minute completion/review timer.
5. Log the result and schedule re-solves (+2, +7, +21 days). Stop.

Use a visible timer, a fixed start ritual (water, headphones, same desk), and
voice narration/body-doubling when attention is sticky.

### Rules that prevent the restart cycle

- Never create a new plan midweek. Capture the idea in a parking lot and review
  it on Sunday.
- Never change resources because a problem felt bad. Label the failure type,
  then use the current resource's next problem.
- Never compensate for a missed session with a four-hour punishment session.
- If two sessions are missed, restart from the daily floor on the next available
  day; do not wait for Monday.
- Keep novelty intentional: vary the problem domain, not the entire system.

## Sustainable cadence

Weeks 1–2: five 30–50 minute sessions and one 75-minute weekend session.
Weeks 3–8: four 60–75 minute sessions, one mock or system-design session, and
one 90-minute weekend deep-work block.
Weeks 9–13: two coding mocks, two focused repair sessions, one system-design
or behavioral session, and one weekly review.

Target is 8–12 deep hours a week initially, graduating to 12–15 only when the
first cadence is stable for two weeks. Do not begin at 20 hours/week.

## Weekly review (20 minutes, Sunday)

- What was completed? What was retrieved successfully?
- What blocked attention: task size, unclear next action, energy, distraction,
  or avoidance after difficulty?
- Choose exactly one process repair for next week.
- Select five study sessions in the calendar and one fallback slot.
- Update readiness metrics, not self-judgment.

## Readiness sequence

Follow the [24-week roadmap](docs/SENIOR_SWE_24_WEEK_ROADMAP.md) as the primary
sequence. Its six-week phases leave room to build Java fluency, cover DSA and
systems topics, and then practice complete interview loops.

1. **Weeks 1–6:** Java foundations and linear data structures. Establish the
   error log and baseline timed practice.
2. **Weeks 7–12:** Trees, graphs, heaps, and system-design fundamentals.
   Draft leadership stories from real work.
3. **Weeks 13–18:** Advanced graphs, DP, concurrency, and end-to-end designs.
4. **Weeks 19–24:** Mixed timed practice, mock loops, story refinement, and
   targeted repair. Begin applications when readiness evidence supports it.

## First session

Do a 45-minute baseline only. Use TypeScript. Solve aloud, no AI help, and
record: time to clarify, brute force, optimal idea, correct code, test quality,
complexity, and emotional friction. The result determines Week 1; it is not a
verdict on ability.
